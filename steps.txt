# 5. Modify your Python code

Your existing code needs one important addition:

```python
from dotenv import load_dotenv

load_dotenv()
```

Put this at the beginning of `app.py`.

Here is the complete beginner version with LangSmith:

````python
import os
import pyodbc

from dotenv import load_dotenv
from langchain_ollama import ChatOllama


# ============================================
# 1. Load environment variables
# ============================================

load_dotenv()


# ============================================
# 2. Ollama / Qwen3
# ============================================

llm = ChatOllama(
    model="qwen3:4b",
    temperature=0
)


# ============================================
# 3. SQL Server connection
# ============================================

conn = pyodbc.connect(
    "DRIVER={ODBC Driver 18 for SQL Server};"
    "SERVER=localhost;"
    "DATABASE=YourDatabase;"
    "Trusted_Connection=yes;"
    "TrustServerCertificate=yes;"
)


# ============================================
# 4. Database schema
# ============================================

schema = """
Table: Employees

Columns:
EmployeeID INT
Name NVARCHAR(100)
Department NVARCHAR(100)
Salary DECIMAL(10,2)
"""


# ============================================
# 5. Get question
# ============================================

question = input("\nAsk your database question: ")


# ============================================
# 6. Prompt
# ============================================

prompt = f"""
You are a SQL Server expert.

Database schema:

{schema}

Convert the following natural-language question
into ONE SQL Server SELECT query.

User question:
{question}

Rules:
- Only generate SELECT
- Do not generate INSERT
- Do not generate UPDATE
- Do not generate DELETE
- Do not generate DROP
- Do not generate ALTER
- Return only SQL
"""


# ============================================
# 7. Call Qwen3
# ============================================

response = llm.invoke(prompt)


# ============================================
# 8. Get generated SQL
# ============================================

sql = response.content.strip()

sql = sql.replace("```sql", "")
sql = sql.replace("```", "")
sql = sql.strip()


print("\n==============================")
print("Generated SQL")
print("==============================")

print(sql)


# ============================================
# 9. Execute SQL
# ============================================

cursor = conn.cursor()

cursor.execute(sql)

rows = cursor.fetchall()


# ============================================
# 10. Display result
# ============================================

print("\n==============================")
print("Result")
print("==============================")

for row in rows:
    print(row)


# ============================================
# 11. Close connection
# ============================================

cursor.close()
conn.close()
````

The important part is that **LangSmith tracing is enabled through the environment variables**, while LangChain's `ChatOllama` call is automatically traced.

# 10. One important limitation in your current code

There is an important distinction.

Your current application has:

```python
response = llm.invoke(prompt)
```

and then:

```python
cursor.execute(sql)
```

LangSmith will naturally observe the **LangChain/LLM portion**, but your raw `pyodbc` database operation isn't automatically a LangChain run.

For a proper production-style application, we can explicitly trace the SQL execution too.

For example:

```python
from langsmith import traceable


@traceable(name="SQL Server Query")
def execute_sql(sql):

    cursor = conn.cursor()

    cursor.execute(sql)

    rows = cursor.fetchall()

    cursor.close()

    return rows
```

Then replace:

```python
cursor = conn.cursor()
cursor.execute(sql)
rows = cursor.fetchall()
```

with:

```python
rows = execute_sql(sql)
```

Now your trace can conceptually become:

```text
NL-SQL-Ollama
      │
      ├── Qwen3 LLM
      │      │
      │      └── Generated SQL
      │
      └── SQL Server Query
             │
             └── Database Result
```

That's much more useful for debugging.
